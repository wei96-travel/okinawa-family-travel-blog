# Okinawa Family Notes 流量與收入營運計畫

更新日期：2026-07-31

這份文件是網站接下來的共同方向。Codex 與 Claude Code 每次開始文章、SEO、連結、社群、圖片或收入相關工作前，都要先讀本文件，再依 `AI_HANDOFF.md` 的最新進度接續，不得各自重新發明一套計畫。

## 一、目前位置

- 網站主體：繁體中文沖繩親子自由行內容。
- 已完成文章：44 篇。
- Search Console 最新紀錄：77 次點擊、1,400 次曝光、CTR 5.5%、平均排名 7.2。
- 現階段仍是流量成長期，不把文章改成商品目錄，也不為了短期收入破壞閱讀體驗。
- 現有收入入口：Shopee、Trip.com、Klook。
- 現有缺口：部分預訂與商品入口只有文字按鈕，缺少實際圖片、選擇理由與點擊比較資料。

## 二、每次開始前固定閱讀順序

1. `AI_COLLABORATION.md`：永久規範。
2. `AI_HANDOFF.md`：上次做到哪裡、誰正在處理、哪些頁面正在觀察。
3. `content/content-plan.md`：文章庫與搜尋意圖，避免重複。
4. `content/seo-growth-roadmap.md`：內容集群與資料判斷方式。
5. `content/affiliate-product-workflow.md`：商品與預訂連結規則。
6. 本文件：流量、連結、圖片、多語言與收入順序。
7. 最新的 Search Console、GA4、社群與分潤週報。

聊天紀錄只能補充背景，不能取代以上文件。

## 三、關鍵字與文章決策流程

每一輪只選一個主要搜尋意圖，不同時大改多個主題。

1. 先看 Search Console 近 28 天與近 3 個月資料。
2. 優先找平均排名 5 到 20、已有曝光但答案還不完整的查詢。
3. 檢查現有文章是否已回答同一意圖。
4. 已有文章能補強就補舊文；只有明確新問題才開新文章。
5. 查看搜尋結果前 10 名的內容配置，只拿來判斷缺口，不抄內容。
6. 票價、交通、設施、安全、法規與營業資訊以官方來源核對。
7. 寫作前先安排主關鍵字、支援問題、FAQ、站內連結與可能的轉換位置。
8. 完成後做事實、真人閱讀、手機畫面三輪檢查。
9. 建置、上線、正式網址、圖片、canonical、sitemap 與 Search Console 都要確認。
10. 再從文章拆出輪播、Reel 或 Facebook 長文，不反過來用社群文硬湊文章。

### 選題評分

| 項目 | 分數 |
| --- | ---: |
| Search Console 已有查詢或曝光證據 | 30 |
| 搜尋意圖清楚、能解決家庭的具體焦慮 | 20 |
| 能補強現有內容集群與站內連結 | 15 |
| 有官方資料或自己的照片可支撐 | 15 |
| 有自然的預訂、商品或數位產品銜接 | 10 |
| 能拆成社群內容而不重複文章 | 10 |

同一輪先做最高分題目。沒有資料支撐的靈感先放候選清單，不插隊。

## 四、連結不是越多越好，要各自有工作

### 站內連結

- 一般文章安排 3 到 5 個真正相關的站內連結。
- 主題總整理或行程入口可安排 6 到 10 個，但要分段，不堆在同一區。
- 至少包含一個上層入口、一至兩篇補充文章，以及讀者下一步最可能需要的頁面。
- 連結文字要說清楚點進去會看到什麼，不重複使用模糊的「看更多」。

### 官方外部連結

- 用來支持票價、營業時間、法規、交通、設施與安全資訊。
- 只在需要核對的句子附近出現，不把參考來源集中成一長串。
- 競品只能用來研究搜尋意圖，不作為事實來源。

### 商品與預訂連結

- 一般文章以 0 到 3 個為原則；沒有自然需求就不放。
- 住宿、用品或票券整理頁可以較多，但必須依情境分組並提供比較理由。
- 每個入口要回答：適合誰、解決什麼、先注意什麼。
- 不使用「最便宜」「必買」「保證」等無法長期證明的說法。
- 技術上保留點擊追蹤與 `rel="sponsored"`；公開文字依專案既有規範處理。

## 五、圖片式連結卡片

第一階段先改：

1. `/okinawa-family-trip-booking`
2. `/okinawa-family-travel-gear`

### 飯店卡片

- 一張能辨識實際飯店的照片。
- 飯店名稱。
- 適合的家庭或行程。
- 一個最重要的注意事項。
- 查看房型或比較住宿的按鈕。
- 圖片、卡片與按鈕分開記錄點擊位置。

### 商品卡片

- 一張單一商品照片，不用多個商品拼在一起。
- 商品名稱與用途。
- 為什麼挑它。
- 規格、使用或攜帶限制。
- 查看商品按鈕。

### 圖片來源規則

- 優先使用聯盟後台明確提供的商品圖、橫幅、工具或媒體素材。
- 其次使用品牌或飯店明確授權的媒體素材。
- 自己拍的照片可用於情境與實際體驗，但館方限制商業用途時仍要先核對。
- 不直接抓搜尋結果、賣家頁面或飯店訂房頁圖片另存上站。
- 沒有實際照片時寧可先保留文字卡片，也不使用會讓讀者誤認為實景或實品的圖片。
- 圖片轉成 WebP、補上尺寸與替代文字，並確認手機載入速度與裁切。

### 驗證方式

- 改版前記錄 14 天點擊基準。
- 改版後再觀察 14 天。
- 比較頁面瀏覽、卡片點擊、按鈕點擊與實際平台轉換。
- 沒有提升就改圖、文案或位置，每次只改一個變因。

## 六、多語言計畫

多語言是後續成長測試，不是現在把 44 篇文章一次機器翻譯。

### 啟動條件

符合下列條件再啟動第一階段：

- Search Console 連續四週出現可辨識的非繁中地區或外語查詢需求。
- 至少有 3 篇適合國際旅客、資料完整且能長期維護的文章。
- 對應的票券、住宿或工具入口能服務該語言讀者，不把台灣專用連結原樣搬過去。
- 有人力做人工校對與後續更新。

### 第一階段

- 先做英文 `/en/` 入口與 3 篇完整文章。
- 每個語言使用獨立網址與自我 canonical。
- 正確建立繁中、英文與 `x-default` 的 `hreflang` 對照。
- 每頁只呈現一種主要語言。
- 提供使用者可操作的語言切換，不依 IP 或瀏覽器語言強制跳轉。
- 觀察收錄、曝光、點擊與閱讀後，再決定是否增加日文或擴大文章數量。

## 七、分潤以外的收入

### A. 數位產品

適合最先測試，因為可以直接使用現有文章與整理能力：

- 沖繩親子行前檢查表。
- 3／4／5／6 天可刪減行程表。
- 租車取還車、加油與事故處理速查表。
- 親子景點 Google Maps 清單與區域整理。
- 行李、奶瓶、雨天與海邊用品檢查表。

先做一個小型產品驗證需求，不一次製作整套。

### B. 行程健檢或內容服務

- 提供使用者已排好行程的節奏、車程與親子風險檢查。
- 不代訂票券、住宿或交通。
- 正式收費前先確認台灣旅行業相關規定與服務邊界。
- 先從固定格式、固定時間的服務測試，不接受無上限來回修改。

### C. 網站廣告

- 可評估 Google AdSense，但不是現在的第一收入來源。
- 啟動前先確認原創內容、導覽、政策與手機閱讀體驗。
- 流量太低時收益有限，且廣告可能妨礙閱讀，所以先把自然流量和回訪做起來。

### D. 品牌內容與 UGC

- 有穩定流量、社群數據和作品案例後，可承接飯店、景點、租車、親子用品的內容製作。
- 可以做文章、輪播、短影音腳本與實拍素材。
- 必須保留編輯判斷，不因合作改寫成誇大推薦。
- 發布與標示方式要符合平台、廣告與相關規定。

### E. 原創照片與內容授權

- 將自己的沖繩照片依景點、住宿區、交通與美食整理成可搜尋素材庫。
- 保留原始檔、拍攝時間、地點、人物同意與館方限制紀錄。
- 未來可提供網站、品牌或媒體單次使用授權。

### F. LINE／Email 名單

- 現階段先用免費檢查表或更新通知累積願意回來的讀者。
- 之後才銜接數位產品、行程健檢或新文章通知。
- 不大量推銷，也不把讀者資料交給第三方。

### G. 社群平台收益

- Facebook、Instagram、TikTok 或 YouTube 的平台分潤只當額外收入。
- 資格與方案會變動，符合條件時再查官方規定，不把整個收入計畫押在平台獎勵。

## 八、收入優先順序

1. 把現有 Shopee、Trip.com、Klook 連結做得更有用、可追蹤。
2. 製作一個小型數位產品，確認讀者是否願意留下資料或付款。
3. 建立 LINE／Email 回訪入口。
4. 有固定流量後再測試 AdSense。
5. 有社群作品與數據後再接品牌內容、UGC 或照片授權。
6. 行程健檢確認服務邊界後再小規模測試。

## 九、每週檢討表

每週六至少記錄：

- 新文章、舊文補強與社群發布數量。
- 索引狀態與尚在等待中的網址。
- Search Console 點擊、曝光、CTR、平均排名與前 10 個查詢。
- GA4 自然搜尋使用者、熱門頁面與閱讀情況。
- Shopee、Trip.com、Klook 的點擊與轉換。
- 圖片卡片點擊率。
- LINE／Email 新增人數。
- 各收入來源金額。
- 本週只選一個需要改善的變因。
- 下週兩篇文章與一個舊文／轉換測試。

## 十、下一步

1. 先確認 Trip.com、Shopee 與 Klook 後台有哪些可合法使用的圖片素材或工具。
2. 為住宿頁與用品頁建立共用圖片卡片元件。
3. 先上 3 張飯店卡與 3 張用品卡，記錄 14 天基準與結果。
4. 依最新 Search Console 查詢決定下兩篇文章，不從舊願望清單直接挑。
5. 從現有文章中挑一份最適合做成免費檢查表的內容，開始累積 LINE／Email 名單。
6. 多語言維持候選，達到啟動條件後才做英文 3 頁測試。

## 十一、Facebook／Instagram 導流漏斗

社群不是文章貼完後才補網址。每個題目開始前，先決定讀者會從哪個平台看到、為什麼願意點，以及點進網站後要完成什麼。

### 導流路徑

社群觸及 → 個人檔案 → 網站入口 → 對應文章或專題頁 → 內部連結／票券／住宿／用品 → LINE 或 Email 回訪

不能只看按讚數。每一層都要分開記錄，才知道問題是在內容、簡介、連結入口，還是網站本身。

### Facebook

- Facebook 的任務是直接導流，不把貼文主體寫成廣告。
- 主文先解決一個具體痛點，例如「第一晚住那霸，第二天再往北，真的比較輕鬆嗎？」。
- 主文預設不放外部網址；作者第一則留言放帶 UTM 的對應文章網址。
- 輪播、Reel 與長文不能只是同一份內容換格式。長文要補新的判斷、失敗經驗或實際安排。
- CTA 不寫「完整內容請點首頁」。要寫清楚點進去會看到什麼，例如「住宿區比較表和帶小孩的移動安排，我整理在第一則留言」。
- 發布後確認公開範圍、圖片或影片完整、第一則留言連結可開啟，再記錄公開貼文網址。

### Instagram

- Instagram 的第一任務是收藏與分享，第二任務才是進個人檔案與點連結。
- 輪播第一張只放一個明確問題；Reel 前 3 秒先出現情境與痛點，不先講網站。
- 貼文 CTA 要指向明確成果，例如「首頁連結有第一次去沖繩的住宿區判斷表」。
- 貼文發布當天或隔天補一則限時動態，用連結貼紙直接連到對應文章，並搭配投票或問題貼紙。
- 個人檔案置頂三篇：網站用途、第一次去沖繩住哪裡、租車或行程核心攻略。
- 不把 IG 當成縮小版 Facebook；相同主題可共用研究，但文案、開頭與畫面要依平台重做。

### 社群入口頁

- 個人檔案不要長期只連一般首頁，也不要放一排沒有優先順序的連結。
- 建立手機優先的 `/start` 入口頁，第一版只放三個選擇：第一次住哪裡、租車自駕、景點與行程。
- 每個選擇直接進對應文章或專題頁，不先塞分潤連結。
- 入口頁載入速度、按鈕文字與手機可讀性要實際檢查。

### 追蹤規格

Facebook 第一則留言：

`utm_source=facebook&utm_medium=organic_social&utm_campaign={topic}&utm_content=carousel|longform|reel`

Instagram 個人檔案或限時動態：

`utm_source=instagram&utm_medium=organic_social&utm_campaign={topic}&utm_content=bio|story|carousel|reel`

每週記錄：

- 觸及人數與非追蹤者觸及。
- Reel 前 3 秒留存、平均觀看與完播。
- 收藏、分享、留言與個人檔案瀏覽。
- 網站連結點擊與 GA4 對應工作階段。
- 文章閱讀後的內部連結、住宿、票券或用品點擊。
- 自己兩個測試帳號的互動另外標記，不算自然成效。

### 七天診斷

- 觸及高、個人檔案瀏覽低：開頭或 CTA 沒讓人想繼續。
- 個人檔案瀏覽高、網站點擊低：簡介、連結文字或入口頁不夠清楚。
- 網站點擊有、很快離開：文章開頭、手機畫面或內容承諾不一致。
- 文章有人讀、相關連結沒人點：推薦位置、圖片卡片或選擇理由需要調整。
- 觸及很低：先改第一張或前 3 秒，只測一個變因，不急著增加發文量。

### 第一輪 14 天測試

1. 主題用「第一次去沖繩住哪裡」，承接現有文章與住宿連結。
2. Facebook 發一篇新的獨立長文，不重複已發布的住宿輪播；連結放第一則留言。
3. Instagram 使用尚未在 IG 發布的住宿輪播，隔天補限時動態連結貼紙。
4. 兩邊使用不同 UTM，七天與十四天各記一次結果。
5. 同期只修改一項：開頭、CTA、簡介或入口頁，避免看不出是哪個改動有效。

Meta 已在 Instagram 專業主控板提供依帳號狀況調整的 Best Practices；每週檢討時應一併查看，而不是固定套用網路上的通用發文公式。Facebook 與 Instagram 都優先使用自己拍攝或實際製作的原創素材，避免只搬運他人的影片或圖片。
