# 搜尋、分潤與前十名配置執行計畫

日期：2026-07-27  
狀態：執行中  
主責：Codex（策略、SERP 盤點、內容與驗收）；Claude Code（候選研究）；wei96（聯盟後台中實際商品選擇與社群發布決定）

## 目的

不把分潤留到「有流量以後」才做。每個有商業決策意圖的頁面，在解答問題之後都要有一條已核對的下一步；同時以 Google 前十名結果確認讀者期待的內容型態與商業配置。

成效不是連結數，而是：讀者找得到答案、願意前往比較或購買、而且知道那是聯盟連結。

## 不可違反的限制

- SEO 記分卡中的冷卻期優先。安全座椅頁在 2026-07-30 前不改；美麗海頁維持既定觀察期；301 舊休息點網址只保留轉址、不新增連結、不改寫搏短期數字。
- 前十名只用來研究搜尋意圖、內容型態與商業元件位置；不抄內容、不把競品當事實來源。
- 住宿與租車只放已確認的 Trip.com 連結；用品只放已確認的 Shopee 連結。連結未確認時只保留候選與搜尋詞，不硬塞按鈕。
- 價格、庫存、兒童規定、停車與設施皆需標示查詢條件，並以官方或第一方資料核對。
- 一次只測試一個改動：內容、標題／摘要、CTA 位置、CTA 文案四者不可在同一觀察期一起變。

## 工作順序與交付物

### 第 0 步：每日選題閘門（每次動工前）

1. 讀最新 Search Console、SEO 記分卡與既有實驗狀態。
2. 把候選分成：可改善舊文、可寫新文、僅研究、冷卻期跳過。
3. 只有「已有曝光且不在冷卻期」的頁面才可改動；沒有安全候選就做 SERP／商品／內鏈研究，不用日更湊數。
4. 在 `AI_HANDOFF.md` 記錄被選與被跳過的原因。

### 第 1 步：建立三份前十名分潤配置表（先做，不發文）

建立在 `research/serp-affiliate/`，每份至少涵蓋一個主要查詢與 Google 前十個自然結果：

1. `rental-car.md`：沖繩親子租車、沖繩租車加油、沖繩租車行李／推車。
2. `family-stay.md`：沖繩親子飯店、那霸親子住宿、恩納親子飯店。
3. `family-gear.md`：沖繩親子推車、沖繩親子行李清單、沖繩海邊用品。

每筆結果固定記錄：

| 欄位 | 要記錄的事 |
| --- | --- |
| 查詢與日期 | 使用的關鍵字、查詢日期、地區／語言設定 |
| 結果類型 | 攻略、比價、OTA、電商、論壇、官方頁 |
| 解答方式 | 首屏回答、比較表、FAQ、工具或清單 |
| 商業元件 | 無、廣告、比價、聯盟按鈕、商品表、單一產品 |
| 出現位置 | 首屏、問題解答後、表格內、文末；不記錄或複製文案 |
| 揭露與限制 | 是否有廣告／聯盟揭露、是否提醒價格或條件變動 |
| 我們的判斷 | 值得採用的讀者路徑、不可採用的誤導做法 |

完成定義：三份表各有 10 個結果、可追溯 URL 與日期，且都產出一條「本站要放在哪個決策點」的結論。

### 第 2 步：依意圖配置分潤，不依文章數湊連結

| 頁面意圖 | 分潤配置 | 上限與條件 |
| --- | --- | --- |
| 資訊型：規定、加油、流程、保險 | 原則上不放商品；若讀者完成判斷後需要比價，可放 1 個租車／住宿比較入口 | 不把 Shopee 塞進證件、保險或法規文 |
| 住宿／租車決策型 | 先講區域、空間、取消、停車與取還車條件，再放 1 個相符 Trip.com CTA；需要時加 1 個「查看同日選項」入口 | 一次只出現一次短揭露；每個 CTA 都有 `trip_sub1` 與 GA4 事件 |
| 用品情境型 | 先列風險與挑選條件，再給 1 至 3 個已核對 Shopee 選項或搜尋詞 | 每個商品要寫適用情境、限制與查詢日期；沒有實際連結就不假裝推薦 |
| 行程／景點型 | 預設不放分潤；只有讀者正要決定住宿、租車或必要用品時才連到相符決策頁 | 不在文章開頭或段落間重複 CTA |

### 第 3 步：第一輪執行清單

1. **租車群集**：先完成前十名表；之後以最新查詢判斷是否改善加油頁。若仍是「排名約第 5 至 10、曝光但零點擊」，只測一個摘要／首屏解答或租車比較 CTA，不同時改標題與內容。
2. **住宿群集**：用前十名表檢查現有那霸、恩納與預訂入口的 Trip.com CTA 是否真的在「選區域、選飯店」之後。補足已核對的兒童、停車、設施條件，不加未核對飯店。
3. **用品群集**：先盤點推車、夏季清單、海邊清單的已核對商品缺口；只補可驗證規格、適用情境與限制，不因品類熱門就增加商品數。
4. **冷卻期頁面**：安全座椅、301 舊網址、美麗海只更新數據紀錄與研究，不改頁面。

## 每篇／每次優化的完成定義

1. 官方或第一方資料已核對，且連結與產品狀態已確認。
2. 前十名配置表已完成，並明確寫出本站採用或不採用的配置理由。
3. 聯盟連結只出現在決策點，附一次短揭露與限制；Trip.com／Shopee 追蹤參數、`rel="sponsored noreferrer"` 與 GA4 事件完整。
4. `content:audit:strict`、Next.js build 通過。
5. 正式站驗收：文章、canonical、sitemap、圖片、CTA 均回應成功；輪播需以公開預覽頁確認桌機與 390px 手機寬度均無溢位且 8 張完整載入。
6. `AI_HANDOFF.md`、SEO 記分卡、內容計畫、社群進度都已記錄；只暫存本次檔案後才提交推送。

## 每週檢討與判斷標準

每週固定回看：Google 點擊、曝光、CTR、平均排名、GA4 `affiliate_click`、各 CTA 點擊率與可歸因的訂單／佣金（若聯盟後台提供）。

- 曝光增加、CTR 偏低：先檢查搜尋意圖與摘要／首屏，不立刻加商品。
- 有閱讀或排名、CTA 點擊低：檢查 CTA 是否太早、產品是否真正解決情境、比較條件是否不足。
- CTA 有點擊但沒有佣金：檢查連結、深層頁、日期／房型／庫存摩擦與使用者意圖，不以增加按鈕數量處理。
- 沒有可用數據或頁面還在冷卻期：只研究與記錄，不改動。

## 這份計畫不做什麼

- 不複製前十名文案、版型或誇大話術。
- 不把所有文章改成商品清單。
- 不用固定「每篇至少幾個連結」當 KPI。
- 不提前動冷卻期實驗頁，或為了分潤破壞文章主題。
